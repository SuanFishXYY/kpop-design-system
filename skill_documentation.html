核心定位

🎹 风格优先 (Style-first)

任意 idol 都可凭设计风格专长被召集，显式名字/团体仅作辅助召回信号。引擎按 brief→specialty 匹配度给所有 idol 排名，派生 anchor 团体，cap 在 5/7。

🎭 角色发言 (In-character)

每位 idol 都有确定性说话人格：tone（12 色调）、signature phrase、speech habits、negotiation levers、hard veto。0 人落在默认 tone。

🏠 宿主 AI 原生 (Host-AI native)

用户已在 Claude/Copilot/Cursor 里，宿主 AI 就是 LLM。JS 引擎只保结构、投票、判决的确定性；成员发言由宿主 AI 原生执行。

⚡ 零配置 (Zero-config)

无 API key、无 provider 抽象层。v3.4.3 删掉了 DeepSeek/Claude/Gemini wrapper，因为宿主 AI 本身就能跑协议。

关键词：K-pop · 工业级视觉策略 · 多智能体议会 · 加权陪审团 2/3 表决 · 团魂否决 · 用户评委 · era 锁定 · comeback cycle · 5 媒介一致性 · 4 代审美 lint

Idol 说话 DNA（7 项）

每位 idol 都被注入确定性人设，0 人落在默认 tone。以下来自 FEMALE-IDOL-ROSTER。

01
🎭 Tone 色调
12 色调枚举：温暖长辈 / 清冷姐姐 / 活力少女 / 暖心姐姐 / 干练队长 / 豆离古怪 / 贵气女王 / 俏皮女孩 / 腼腆内向 / 中性飒爽 / 御姐毒舌 / 温柔治愈。
02
💬 Signature Phrase
每人一句标志性台词，作为发言开头/结尾的确定信号，帮助用户识别“是谁在说话”。
03
🔁 Speech Habits
语言习惯：句长偏好、口头禅、是否用反问、是否使用专业术语 vs 俚语。
04
🤝 Negotiation Levers
让步杠杆：在 R2b 谈判中会交换/坚持什么（如“可让字体但坚持配色”）。
05
🚫 Hard Veto
硬否决项：某些 idol 对特定风格/手法有不可逾越的底线（如“绝不接受廉价渐变”）。
06
🎨 Specialty
设计专长标签：决定能否被召集。如 Y2K / cyberpunk / 极简 / 手绘 / 排版 / 配色 / 动效。
07
🏠 Anchor Group
所属团体（52+ 团魂）· 用于派生 veto 权与团魂一致性检查。

R3 立场分类（conflict-aware）

R3 投票时每位 idol 必须表明立场，引擎按立场加权汇总。

AGREE 同意 +1.0

完全支持当前方案，认为可直接执行。

RESERVE 保留 +0.5

总体同意但有疑虑，需附加条件。会列出修改点。

COMPROMISE 妥协 +0.7

放弃部分坚持换取整体推进，贡献 R2b 谈判结果。

DISSENT 反对 +0

明确反对，必须给出替代方案或否决理由。

关键引擎机制

🔒 Era 锁定

一旦 brief 锁定 era（如 Y2K / cyberpunk），所有后续发言与投票必须在 era 范围内，避免风格漂移。违反者被引擎标记为 generation-lint 错误。

🌐 5 媒介一致性

设计决议必须同时覆盖 5 个 touchpoint（web / social / print / motion / merch），引擎检查跨媒介风格一致性。

🧹 4 代审美 lint

对生成的设计输出做代际审美校验（1代经典 / 2代过渡 / 3代现代 / 4代前沿），防止产出过时或超前于目标受众的视觉。

🔗 Dead-link 校验器

输出前扫描所有引用的资源链接，确保无死链。是 v3.7.0 新增的输出守门机制。

职责分离原则

⚙️ 引擎（确定性）

JS 代码负责：brief 解析、名单召集、轮次调度、token 预算、冲突检测、加权投票、判决、导出、校验。这些必须可测试、可复现。

🧠 宿主 AI（生成性）

宿主 AI 负责：每位 idol 的人设发言、R2 质询内容、R2b 谈判措辞、最终设计 brief 文案。引擎只提供结构与约束。
